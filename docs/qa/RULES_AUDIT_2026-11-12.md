## R-01 / P1: неправильное допущение о нижней карте темы

| Действие | Текущая реализация | Ожидание после уточнения владельца |
|---|---|---|
| Предмет → предмет своей категории в нижнем поле | Разрешено, объединяется группа | Сохранить |
| Предмет → карта темы своей категории в нижнем поле | **Разрешено** | **Запретить** |
| Карта темы → пустой верхний слот | Разрешено, запускается сбор | Сохранить |
| Предмет → запущенная категория в верхнем слоте | Разрешено, увеличивается счётчик | Сохранить |
| Предмет → пустой верхний слот | Отказ, без расхода хода | Сохранить |
| Предмет → другая категория | Отказ, без расхода хода | Сохранить |

Нельзя распространять запрет на добавление предметов в **верхнюю** запущенную категорию: это основное действие сбора.

**Причина пропуска.** Требования §4.2 прямо разрешили объединение любых доступных групп одной категории, включая лидера, и отдельно разрешили полную группу с лидером внизу. Вступление к разделу честно называло это нашим выбранным правилом для неустановленных краевых случаев. `applyBoard()` проверяет совпадение category, затем `normalize()` оставляет лидера спереди; отдельного запрета назначения на нижнего лидера нет. Генератор, solver и прежние тесты используют тот же переход. Аудиторский oracle реализован отдельно, но повторяет **то же смысловое допущение**. Его согласие с движком не проверяет замысел игры.

**Что подтверждает референс.** Повторно просмотрены локальные исходные записи Hitapps и AZUR из реестра источников. AZUR около 00:21–00:36 показывает запуск верхней категории и укладку её членов; Hitapps около 01:53–01:58 показывает Review → Feedback, где цель — обычная словесная карта, без золотого оформления лидера. Эти сцены не доказывают разрешение предмет → нижняя карта темы. Подтверждённого изолированного принятия/отказа именно такого хода в просмотренных сценах нет. Не выдаём отсутствие примера за доказанный запрет конкурента. Уточнение владельца теперь определяет ожидаемое правило нашей игры.

**Масштаб.** Из 108 опубликованных контрольных путей **73 содержат 151 такой перенос**: **52/80 кампаний и 21/28 daily**. Первые примеры: уровень 4, шаги 3 и 13; уровень 5, шаг 20; уровень 6, шаг 1; уровень 8, шаги 5 и 18. Точные команды и ID находятся в `results.json → impact`. Это число утративших валидность прежних путей, **не число доказанно нерешаемых уровней**.

Для 15 раздач выполнен отдельный BFS с запрещённым спорным переносом и лимитом 8 000 извлечённых состояний. Найдены решения для 1, 2, 21–25 и 35; для 3, 6, 10, 19, 26, 64 и 80 получен UNKNOWN. Ни один UNKNOWN не объявлен нерешаемостью.

Более того, для уровня 6 вручную проверен исправленный порядок первых трёх действий: **«Свет» → верхний слот 2; «Фонарик» → этот верхний слот; «Посуда» → верхний слот 1**. Дальше работает прежний остаток пути; число ходов и остаток бюджета не изменяются. Полный альтернативный путь записан в `manualStrictWitness`. Это показывает ограничение короткого BFS и возможность переиспользовать часть банка; опубликованный путь не заменён.

## R-02 / P2: легальная попытка становится незагружаемой

`dispatch()` не ограничивает растущую историю Undo. `decodeSave()` отказывается читать историю длиннее 300 снимков. На уровнях 1–2 бюджет бесконечный, поэтому ограничение достижимо обычными разрешёнными действиями даже без расходных помощников.

Воспроизведение на уровне 1:

1. Выполнить первые пять обычных действий контрольного пути. Остаётся «Дятел» (`birds_2`) и свободный нижний столбец.
2. Переносить его между двумя нижними столбцами 296 раз. Все 301 действия приняты, карта и ресурсы остаются корректными, партия ещё playing, бюджет null.
3. Перезапустить приложение/перезагрузить страницу: **«Не удалось открыть партию / Повреждена история»**.

Исходное сохранение не стирается, но штатного продолжения нет. Это реальная достижимая ошибка, а не искусственное редактирование JSON. Автоматическая проверка воспроизводит её через движок; отдельный браузерный сценарий выполняет все 301 действия touch-вводом.

Минимальное исправление: общий предел истории при всех добавлениях (обычный ход и Joker), совпадающий с контрактом загрузчика. Для уже записанных длинных **валидных** историй — совместимая обрезка старейших снимков после проверки каждого сохраняемого состояния, без сброса поля, кошелька, helper charges, counted edges и наград. Нельзя просто добавить `slice()` при новых ходах и оставить прежние попытки незагружаемыми. Проверки: границы 299/300/301/1000, reload, Undo после обрезки, активная и припаркованная попытки, legacy migrations.

## R-03 / P3: защитная проверка сохранений неполная

Загрузчик принимает искусственно повреждённые состояния с разными категориями в одном верхнем слоте, верхним слотом без лидера и частично «собранной» категорией. Карты при этом уникальны и количество сохранено: `assertBoard()` проверяет прежде всего целостность ID, ключи, бюджет и фазу, но не все семантические инварианты зон.

Эти состояния **не получены разрешёнными ходами** в аудите. Это задача защиты от повреждённого файла/будущего дефекта, а не ещё три доказанных способа обойти правила в интерфейсе. Приоритет ниже R-01/R-02. Усилить проверку верхних слотов, собранных категорий, открытости доступных зон и ordered-префиксов, сохраняя отказ без перезаписи исходных данных. Перед ужесточением прогнать реальные совместимые старые активные/припаркованные попытки и Undo.

## Что прошло проверку

Ручная таблица содержит **34 явно заданных случая**, включая спорное текущее разрешение, которое не считается правильным только из-за зелёного результата. Через второй переходный алгоритм проверены **6 068 состояний, 336 942 действия**: 35 635 принятых, 301 307 отказов. Кандидаты перечисляются по всем существующим зонам, включая запрещённые источники foundation и назначения waste, а также оба действия draw/recycle. Они не берутся из production `legalCommands()`.

Выборка включает каждый шаг всех 80+28 фиксированных путей, конечные состояния и два воспроизводимых альтернативных прохода по каждой раздаче. Дополнительно проверены **10 838** переходов профиля/Undo/отказов. Сохранение карт, уникальность, чистота верхних категорий, наличие лидера, открытость waste, закрытость stock и полнота collected проверяются отдельными утверждениями. Для принятых действий проверяются неизменность входа, точная доска и стоимость; для отказов — поле, бюджет, ресурсы, история и reset только progress серии.

| Область | Результат в проверенных случаях |
|---|---|
| Чужая категория, пустой верх без темы, закрытый источник, источник сверху | Отказывают, хода не отнимают |
| Доступная группа | Переносится целиком; скрытая карта открывается атомарно |
| Верхний сбор | Только свой category, очистка полной категории, победа на последнем разрешённом ходу |
| Колода / повтор | Draw-one, только последний waste, точный порядок без shuffle; по одному ходу |
| Undo | Поле, открытие, бюджет, завершение группы, ключи и замок откатываются вместе; кошелёк/серия/потраченные помощники не возвращаются |
| Неверный drop / отмена жеста | Отказ и cancel различаются; бюджет не расходуется, новая запись Undo не создаётся |
| Ordered | Интервалы и префиксы; пропуск ранга отвергается с конкретной причиной |
| Joker | Блокирует исходный пакет, принимает один пакет, не принимает второй; charge/once-per-attempt не возвращаются Undo |
| Замок | Нет доступа в обе стороны до трёх ключей; третий ключ, unlock и flip атомарны; Undo/reload согласованы |
| Hint | Используется актуальное уточнение 0.9.2: только найденное продолжение, без списания при UNKNOWN/UNSOLVABLE/ошибке/таймауте; повтор бесплатный |
| Награды и окончание | Проверенные повторные события не дублируют выдачу, выигрыш имеет приоритет над нулём ходов |

Полные проверки и ограничения источников — ниже. Статистика согласия двух алгоритмов устанавливает соответствие **нашему контракту**, а не паритет Hitapps и не человеческую понятность/интерес.

Оценки — инженерный прогноз, не измеренная длительность. Особо рискован пакет правил: поле текущей попытки и parked другого режима могут требовать разных правил. Нынешнего глобального номера Save недостаточно для бездумного обновления обоих. Нужен явный вариант совместимости до миграции.

Итоговая приёмка будущего исправления: четыре комбинации нижних лидеров/членов в обе стороны; все назначения upper; drag/tap/границы; повтор колоды и Undo; last-move win/exhaustion; Joker/order/keys; исходные и альтернативные маршруты всех 108 задач; старые сохранения и parked; фактическая новая запись показанного уровня 6. Проходимость из начала не обещает победу после любого плана игрока. Числовую сложность, графику, награды и рекламу в этот эксперимент не включать.
