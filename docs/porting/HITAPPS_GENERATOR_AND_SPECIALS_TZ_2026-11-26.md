## 1. Целевое устройство: один домен правил, два источника генерации, отдельные задачи

```text
Own LevelInput + versioned config + player history
   -> validate / fixed preset or random / EffectiveBudget
   -> Route: Fresh Initial -> seeded layout/Shuffle -> Final
          OR simulated candidate -> seeded layout/puzzle/pairs
             -> Shuffle modifiers (alreadyShuffled) -> source-shaped bot(s)
             -> candidate select/restore -> Final gold/starter
   -> own immutable Deal + stage receipts / evidence
   -> independent engine/oracle replay + choice/balance checks
   -> versioned bank -> normal issuance/retry -> SaveStore/attempt
   -> same Rules engine (human actions, solver, hint, Undo)
```

Симулятор источника и решатель продукта — разные ответственности. Бот не должен выбирать путь по заранее известному winningPath или seed. Native-бот имеет ограничения/порядок, которых не должно быть у игрока (stock lookahead, пустые destination reservations). Solver/Hint/независимый oracle должны использовать новый **действительный** набор правил, но не ту же реализацию функции перехода в oracle. Правило допуска исходного бота, гарантия прохождения и человеческая сложность — три отдельных заключения. Бот поздно проиграл ≠ UNSOLVABLE; bounded cap ≠ UNSOLVABLE; одна победная трасса ≠ интересные альтернативы.

AZUR остаётся отдельным адаптером `tools/content/azur-dealer.ts` / `build-azur-preset.ts`: отдельный tutorial preset, temporary-copy single descending Fisher–Yates + внешний Unity-model RNG. Не заменять его Hitapps EmbeddedRandom; проверять общую domain/QA регрессию, не дублировать дилеры. Unico и остальные игровые/коммерческие системы сохраняются в реестре без повторной реализации в этом пакете.

Пример собственного TS (точная арифметика; тесты из kit):
```ts
const f = Math.fround;
const away = (x:number) => x < 0 ? -Math.round(-x) : Math.round(x);
function getStepsLimit(base:number,p:number,stable:boolean) {
  return !stable || p === 0 ? base : (base + away(f(f(Math.imul(base,p))/100))) | 0;
}
function easyTarget(dtoMoves:number,dtoPenalty:number,decCoef:number) {
  if (!Number.isSafeInteger(decCoef) || decCoef<1) throw Error('bad config');
  const n = getStepsLimit(dtoMoves,(Math.min(dtoPenalty,0)-decCoef)|0,true);
  if (n<=0) throw Error('nonpositive target'); return n;
}
function withinTolerance(target:number,steps:number,stable:boolean,accuracy:number) {
  return !stable || accuracy<=0 || Math.abs(target-steps) <= away(f(f(f(target)*f(accuracy))/100));
}
```
Acceptance: 130/−5→123; 25/±10→28/22; target 25/10% tolerates 28 not29; 100/+10/15→85 vs 100/−5/15→80. 10 ExtraSteps / restart weight; in-bound and crossing zero; 65 L16–80 plus later/locale/fixed, negative requested seed, bank deterministic. No duplicate outcome when SaveStore retries. Actual local playability report includes distributions, not average only.
