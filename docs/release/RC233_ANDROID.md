## Исправления

R4-UI-A. Phaser переносит только целые слова и редакторские переносы с дефисом. Неизвестное длинное слово вписывается измеренным масштабом подписи. Геометрия карты и касаний сохраняется. Aa даёт исходное полное название. На узком экране кошелёк жизней располагается отдельной строкой, у заголовка и × свои области. Подпись перемешивания в помощниках помещается в ячейку.

R4-UI-B. Пять недельных ступеней свёрнуты под «Все награды недели». Прогресс недели и готовая награда доступны в закреплённой шапке. Ступени находятся после сегодняшних заданий. Сегодняшние задания видны до прокрутки на 320×480, 320×568 и 360×640. Раскрытие, архив, исходные IDs, сохранённые сундуки и награды обслуживает прежний контроллер. Старые недели раскрыты при открытии.

## Инфраструктура

CI проверяет только наличие восьми production-настроек и три существующих подтверждения владельца. `release-readiness.json` хранит булевы результаты без значений секретов. Это не проверка действительности ключа, alias или доставки SDK.

`release.yml` принимает полный `expected_commit`, проверяет checkout и наличие production-конфигурации до компиляции. Для store APK/AAB нужны существующий keystore, три live unit ID и ключ AppMetrica. Сборка проверяет цифровую подпись, точный web payload, production package, Rules4/M1, IAP OFF, флаги и хеши. APK unsigned для R8 остаётся отдельным CI доказательством компиляции.

Обычные события передаются через общий контракт. ILRD пишет независимый delivery ID, currency и целое micros в durable outbox. Геолокация и рекламные идентификаторы в конфигурации AppMetrica отключены. Реальная серверная доставка и данные стороннего рекламного SDK требуют dashboard/device проверки.

## Android · BLOCKED_DEVICE

В рабочей среде Android-устройство и ADB недоступны. Браузерные записи фиксируют интерфейс и контролируемые отказы моста. Для каждого пункта ниже нужно записать PASS/FAIL, время, модель, Android, WebView, версию APK, короткое видео и редактированный logcat. Результаты физической проверки пока BLOCKED_DEVICE.

1. Чистая установка demo APK. Затем `adb install -r` поверх 0.21.4/0.21.5 без удаления данных. До/после сравнить монеты, жизни, active/parked партии, Undo и награды. Production package отличается от debug, поэтому обычное обновление .debug не проверяет миграцию production-пакета.
2. Пройти L1–7 с реальными касаниями. На L6 проверить оба дополнительных слота, перезапуск, фон и force-stop. Проверить L16–32, L80→81, текущий и прежний Daily, нулевые жизни и кошелёк. Оценить safe-area и независимые motion/SFX/haptics.
3. Зафиксировать настоящий Yandex demo banner после обучения. На допустимом переходе после cooldown проверить межуровневую рекламу. Coffee проверять после реальных действий и своего интервала. Обучение, жесты и открытые окна защищены.
4. Для каждого rewarded проверить окно SDK и реальные show/earned/close. Сценарии — победа, Hint/Undo, Continue, оба слота, кошелёк, жизнь. До просмотра записать ресурс, после проверить ровно одну награду. Закрыть до earned и убедиться в отсутствии выплаты. Проверить offline/no-fill.
5. Фон, блокировка экрана, возврат и relaunch во время видео. Сверить cooldown после фактического show. Поздняя квитанция должна доставиться один раз. При потере terminal callback подтверждённый foreground возвращает управление. До definitive terminal второй fullscreen не запускается. Если отказ SDK не удалось воспроизвести, записать «не воспроизведён».
6. `adb logcat -s SolitaireAds` использовать для фаз и receipt ID. Перед передачей скрыть unit ID, ключи, любые личные данные и идентификаторы устройства. APK SHA и сертификат приложить отдельно.
7. После подтверждения demo владелец отмечает три approval vars. С существующей production-подписью запускает Signed Android release на принятом SHA. На разрешённом сетью тестовом устройстве проверить live SDK и AppMetrica dashboard, ILRD delivery ID/валюту/micros. Не нажимать рекламные объявления для теста и не создавать искусственные live показы.
