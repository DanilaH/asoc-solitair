## 5. Контракт, сохранения и включение

Для затрагиваемой механики описать [вход → решение → атомарное изменение состояния → feedback], условия допустимости и отмены, повторы/callback-идемпотентность, ошибки/no-fill — где применимо. Указать владение ресурсом и сроком действия; `shown`, `earned`, purchase receipt и ILRD — разные события. Неплатное право получает собственный grant-контракт, а не фиктивную покупку.

Зафиксировать применимые изменения SaveStore/Undo, совместимость старых сохранений и неизменных deal/attempt IDs, миграцию и возобновление. Для включения указать [конфигурация/флаг → условия активации → наблюдение → откат с сохранением прав игрока]. Если эти контракты не затрагиваются, написать почему; не придумывать миграцию для чисто визуальной правки.

## 6. Проверки и oracle

| Сценарий / риск | Ожидаемый результат и независимый oracle | Среда / source tier | Фактический результат или PLANNED |
| --- | --- | --- | --- |
| [Обычный сценарий] | [Критерий + источник, который его обосновывает] | [NATIVE_STATIC / own-model / NATIVE_ISOLATED / ORIGINAL_RUNTIME; целевой consumer] | [SHA, тест/run/capture или точная оставшаяся проверка] |
| [Ошибка / граница / повтор, где применимо] | [Инвариант сохранений, ресурсов, состояния или UX] | [Unit / browser / Android / реальный SDK — фактическая среда] | [Результат; модель/мок не выдавать за live SDK] |

Выбрать проверки по реальным рискам дельты: независимый gameplay oracle/solvability, SaveStore/Undo, UI/Android, SDK/settlement, негативные и различающие ошибочный алгоритм контроли — где применимо. Не подменять oracle повторением реализации. Для изолированных оригинальных функций указать входы/shims/ветви/контроли; полный оригинальный runtime и целевой Android доказываются отдельно. `UNKNOWN` solver не означает доказанный проигрыш.

Приёмку нашей `PRODUCT_ADAPTED` возможности и точность `SOURCE_PARITY` учитывать отдельно. Отсутствие исходного Android само по себе не доказывает некорректность собственной адаптации; конкретная неизвестная зависимость выбранной механики может блокировать её приёмку. Новый метод, фрагмент кода или зелёный CI не снимают нужные quality gates.
