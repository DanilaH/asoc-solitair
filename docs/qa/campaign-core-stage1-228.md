# №228 · Этап 1. Ядро кампании

База — PR #227, `26c40e7cbddf7117acde956b2c61c98af2728f84`. Кандидат 0.21.2, Android code 53. Политика выдачи `campaign-core-stage1-v1`, профиль `c8-release-v1`.

- L1 сохраняет исходную учебную геометрию и игру без лимита ходов. L2–15 получают по шесть геометрий Rules4. Банк L16–80 расширен 35 сертифицированными раскладами, чтобы на каждом из этих уровней было минимум три. Первые демонстрации на L17–19, L24, L26–28 и L32 сохраняют опубликованные точные позиции. После явного повтора доступны варианты Rules4.
- Выдача использует исследованный RNG и существующие source-shaped authoring pipeline, Priority и независимый Rules4 oracle. Генерация и proof выполняются при подготовке банка. Runtime выбирает геометрию по сохранённому зерну ротации, уже сыгранным вариантам, адаптивному бюджету и Easy Deals. Бюджетные варианты считаются одной геометрией. Палитра спецкарт сопоставляется независимо от цен помощников и предложений слотов.
- Явный перезапуск с L2 запускает другую геометрию. Закрытие игры, reload, Daily, Undo и возобновление используют сохранённую попытку. Перезапуск на состоянии playing не списывает жизнь. После исчерпания ходов повтор использует тот же одноразовый дебет, что PR227. Артефакты старых раздач и идентификаторы первой победы остаются доступными декодеру.
- Доступность обычных помощников определяется состоянием поля с L2. Подсказка L3 и отмена L4 остаются учебными действиями. Перемешивание требует сохранённый заряд и доказанный маршрут. Одноразовый вводный заряд остаётся в прежнем инвентаре при доступных заданиях. Ручной и случайный Джокеры используют разные права. Ходы без лимита доступны на раздачах с конечным бюджетом. Восстановление запаса остаётся возможным на полях с конечным числом оборотов, когда ресурс исчерпан.
- С L6 на подходящем поле независимо доступны нижний столбец за 60 и место для темы за 100 монет. Возможность видео зависит от SDK и сохранённого earned receipt. У нижнего столбца приоритет подсказки, когда обычные столбцы и места темы заняты. В обучение добавлены только контекстные действия. Ранние картинки переиспользуют собственные материалы.
- Обычная кампания заканчивается после L80. Daily доступна отдельно. Выбор раздач доступен в отдельной офлайн QA-сборке. В CI сохранён отдельный архивный профиль PR227 для точного проигрывания исторических тестов. Оба отладочных режима блокируются при упаковке Android.

## Повторяемая проверка

- `npm run qa:hitapps-r4` проверяет полный последовательный проход, паспорт Rules4, старый архив, адаптивные бюджеты и архивные и новые маршруты независимым валидатором.
- `tools/qa/audit-campaign-core-stage1.ts` запускается с `VITE_ASOC_PROFILE=c8-release-v1` и с тем же профилем плюс `VITE_ASOC_ARCHIVE_227=1` для базы сравнения. Сборка через `vite build --ssr`, затем `node <сборка> <отчёт.json>`. Метрики включают размеры, запас, первый сбор, закрытые категории после 20 и 40 действий, развилки, два бот-профиля и маршрут L6 после пропуска доступной карты сброса.
- `tests/unit/campaign-core-stage1.test.ts` проверяет четыре последовательных геометрии L2–15, адаптивную ротацию поздних уровней, сохранённые попытки и помощников. `tests/browser/campaign-core-stage1.spec.ts` выполняет реальные touch-события через обычный интерфейс. С `ASOC_CORE_RECORD=1` этот сценарий записывает видео.
- `tools/content/build-campaign-core-stage1.ts` восстанавливает открывающий банк. Для дополнительных поздних кандидатов использован `build-hitapps-r4-coverage.ts` с `HITAPPS_COVERAGE_LIMIT=1`, seed offset 2000 и 180 попытками на уровень.

Нативные показы, earned/no-fill, геометрия с реальным Android-баннером и человеческий баланс требуют физического плейтеста. Исходные серверные настройки и точная нативная паритетность не подтверждены. Остальные пункты #228 и #226 остаются в очереди следующих этапов.
