## Установка и протокол наблюдений

1. Записать PR HEAD, CI run, SHA APK, отпечаток подписи, модель устройства, Android, WebView, сеть, часовой пояс и размеры видимой области. Проверить `apksigner verify --verbose --print-certs` и `python3 tools/qa/verify-release-apk.py`. Оба встроенных манифеста должны ссылаться на выбранный коммит.
2. Для проверки обновления использовать выделенный тестовый профиль и предыдущий debug APK с тем же package ID и сертификатом. Сделать копию старого профиля, установить через `adb install -r <debug.apk>`. Зафиксировать исходные Deal ID, активную и отложенную попытки, Undo, прогресс, монеты, помощников и неиспользованные права. Не удалять данные между версиями.
3. Для дополнительных повторов на отдельном тестовом профиле сравнить до/после `adb exec-out run-as com.danilah.asocsolitair.debug cat no_backup/solitaire-state-v1/asoc-solitaire.save.v1.json`. Если требуется исходный JSON из независимого аудита, использовать отдельную установку без личных данных, остановить процесс, сохранить копию всего каталога `no_backup/solitaire-state-v1` и поместить тестовые байты на место основной записи через `run-as`. Профиль должен быть сохранён той же одноимённой debug-сборкой и не иметь незавершённых AtomicFile-записей. В опубликованные доказательства включать хеши, сравнение полей и обезличенные логи.

## Сценарии на тестовом SDK

| Шаги | Артефакт и критерий |
| --- | --- |
| Открыть старый профиль. Сделать ход и Undo, перейти в Daily, вернуться в Campaign, вызвать Home, вернуть приложение и перезапустить процесс. На оригинальной дефектной копии после Unlimited → Continue выполнить Undo и повторный запуск. | Запись экрана, Deal ID, глубина Undo, прогресс и права до/после. Повторные открытия используют прежние доски. История и поле согласованы. |
| На нуле жизней вызвать видео и досмотреть. Сверить earned, SaveStore commit и ACK по обезличенным событиям. Повторить запуск после закрытия и уничтожения процесса, включая уже записанный earned. Отдельно начать перед естественным восстановлением. | Одна жизнь/один кредит по nonce, earned и естественное восстановление учтены вместе. Повтор доставки не выдаёт ресурс снова. |
| Прервать видео до earned, выйти в фон во время показа, завершить процесс до показа, затем повторить. Вызвать SDK с недоступной сетью и после восстановления. Зарегистрировать фактический код callback no-fill отдельно от сетевого отказа. | При закрытии без earned нет выдачи, новая попытка допускается после согласования журналов. No-fill подтверждается фактическим кодом SDK. При временной ошибке чтения/записи квитанция остаётся для повтора. |
| Для сбоя I/O на выделенном debug-профиле дождаться начала видео, запомнить режим каталога через `adb shell run-as com.danilah.asocsolitair.debug stat -c %a no_backup` и временно задать ему `chmod 500` через тот же `run-as`. Это блокирует создание файла квитанции. Для отдельного сбоя SaveStore применить тот же шаг к `no_backup/solitaire-state-v1`. После earned/закрытия вернуть исходный режим до перезапуска. Повторить перезапуск после durable записи. | Запись с временными метками показывает переход к durable receipt → saved grant → ACK. Потеря процесса до первой успешной записи остаётся отдельной границей. |
| На L16 включить срочный Unlimited, сверить время со секундомером, свернуть приложение до и после дедлайна. Повторить с force-stop, переводом настенных часов назад, сменой boot count и отложенной кампанией. Затем Continue и Undo. | Native elapsed clock не продлевает право при изменении wall clock. После дедлайна конечный бюджет и Undo остаются валидными. Старое законное право доступно в допустимом состоянии. |
| Запустить Hint из аудиторских позиций L17 и L26 по три раза с исходным состоянием. На коротком портрете измерить фактический баннер, таймер и восстановление. Пройти системный Back, звук и вибрацию. | Снять фактическое время от касания до подсказанного хода или отказа. Записать видимость, отступы и сырые касания без прокрутки, а также System Back и звук/тактильную отдачу. |

Процессный перезапуск выполняется `adb shell am force-stop com.danilah.asocsolitair.debug` с повторным запуском через лаунчер. Для Activity-пересоздания использовать отдельный сценарий на том же профиле, чтобы отличить его от потери процесса. Синтетическая блокировка файлов, локальный браузер и отсутствие сети фиксируются отдельно от естественного provider no-fill.

## Live и плейтест

- Сборка live выполняется из зафиксированной release-ветки на принятом HEAD. Проверить фактический checkout. Существующий workflow требует production signing, три действительных Yandex ad units и ключ AppMetrica. Проверить подтверждённые значения `ASOC_OWNER_ADS_READY`, `ASOC_OWNER_LIVES_ADS_READY`, `ASOC_REWARD_OFFERS_ADS_READY` и соответствие `sdkCapabilities` выбранному контуру. Секреты остаются в CI. Записать SHA сборки, отпечаток подписи и состав. Передавать APK только в согласованный тестовый контур.
- Зафиксировать по одному разрешённому rewarded, interstitial/AdsBreak и banner показу. Для каждого сверить вид показа, окно времени, `deliveryId`, принятый SDK payload и строку в согласованной выгрузке целевого приложения AppMetrica. Отдельно проверить доставку после временной недоступности и повтора без повторной локальной выдачи. Test APK с `impressionRevenue=false` подходит для тестовых показов. Поступление ILRD доказывает целевой live-проект.
- На том же кандидате провести игровые сессии на новом и существующем профиле. На L1–16, L17–30 и поздней кампании записать попытки, время, поражения, доступные восстановления, монеты/помощники и интервал между полноэкранными показами. Отдельно провести сессию без видео и с разрешённым видео. Сопоставить добровольные и прерывающие показы с результатом, экономикой и ограничением AdsBreak/Coffee как одной паузы. Отдельно отметить человеческую оценку темпа и мест, где прекращают игру.

Статус физических сценариев, live и человеческого плейтеста — открыт до приложенных записей с точным коммитом. Браузерные регрессии, Gradle и проверка подписи фиксируются отдельно.
