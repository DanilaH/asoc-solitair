## Почему Q1 ещё не ответил на вопрос «насколько дорого ошибаться»

- На 80 активных кампаниях Q1 подтвердил **325 из 528** проверенных выигрышных продолжений после альтернативного переноса; 203 остались `UNKNOWN`. Среди **всех** классов Q1 есть 505 побед / 384 UNKNOWN / 0 доказанных NO_WIN, но это *выборка из 800 исходных witness-состояний*, а не оценка вероятности победы обычного игрока.
- 263 из 325 выигрышных transfer-продолжений **не возвращаются к нормализованному состоянию до расхождения**. Это сильнее, чем просто «можно ходить», но всё ещё не гарантирует тактическую пользу или человеческую понятность.
- Авторский маршрут **не оптимален**: в старых паспортах 43 альтернативы были короче основного решения. Поэтому «дополнительные ходы по сравнению с witness» — **наблюдаемая разница двух конкретных маршрутов**, а не математически минимальная стоимость ошибки. Отрицательное значение означает, что найденный альтернативный путь оказался короче авторского, и само по себе не доказывает «ошибку автора».
- Наличие `loopsBack` показывает только посещение эквивалентного исходного состояния выбранной нормализации; не означает, что другой перенос был бесполезным для игрока. Частота возвратов в этой выборке не равна частоте в человеческих сессиях.

## Новый воспроизводимый метод

**Часть A — полный cost-профиль выбранных альтернатив.**

```bash
npm run qa:campaign-decisions
npm run qa:decision-cost
```

Первый скрипт (уже существовавший Q1) пишет `.authoring/content8/campaign-decisions.json`, второй — `.authoring/content8/campaign-decision-cost.json`. Второй проверяет:

1. идентичность, уровень, слотную конфигурацию и полный охват **1–80**;
2. непротиворечивые remaining-moves на исходном witness и альтернативном первом ходе;
3. **сохранение расхода ходов** до конечной победы по записанному пути;
4. раздельные распределения по классу действия, ранней/средней/поздней фазе, активной кампании, архивам, директору и открытым бонусным слотам;
5. отдельно `UNKNOWN`, `NO_WIN`, победы с/без возврата на исходное состояние; без присвоения цены невыясненным исходам.

Для каждого конечного выигрышного пути с числовым лимитом:

`extraMovesVsWitness = (issuedBudget − authoredWitnessLength) − verifiedAlternativeMovesLeft`.

Положительное значение = данный выигрышный путь потратил больше ходов; отрицательное = меньше. **Не минимальный regret, не оценка чувствительности игрока, не сравнение с оригинальным Android.** У безлимитных учебных раздач значение `null`, не вымышленный ноль. Исходная Q1-сводка 0.20.3 указывала SHA-256 `c1a3fc7341863d7a9d4439fe41fa985d38fb34644ad87b2879d4ce363f7b630c`; повторная сборка выводит фактический input hash, который нужно сравнить, а не автоматически считать совпадающим.

**Часть B — углубление выбранных неизвестных переносов.**

```bash
npm run qa:decision-deep
```

`tools/qa/deepen-c8-unknown-transfers.ts` читает **тот же Q1-отчёт**, проверяет exact published deal ID, воспроизводит Q1 witness-позицию, `prefix`, исходный перенос и оставшийся бюджет через production `applyBoard` + независимую `advance`. Выбирает до 18 различных проб в нескольких классах/фазах, с первыми приоритетными уровнями 15/26/31/45/70 и дополнительными 16/38/78/80. Ограничение поисковика повышено до **3 200 состояний** на выбранную пробу; ordinary-эвристика имеет собственный предел 1 200. Найденный путь считается `VERIFIED_WIN` **только после полного двойного replay до `won`** с оригинальным лимитом. Остальное остаётся `UNKNOWN_LIMIT`, даже если ограниченный поиск не нашёл ни одного решения; не объявлять `NO_WIN` без действительно полного доказательства для данной конфигурации.

Результат — `.authoring/content8/campaign-unknown-transfer-deep.json` и краткие `C8_Q1B_DEEP` строки CI.

**Обязательный caveat:** глубина поиска и набор проб отличаются от #69 (28 проб / 900 состояний / все UNKNOWN), поэтому по успешным находкам нельзя утверждать, что #69 был ошибочен. Это дополнительные проверенные пути для другой/частично пересекающейся детерминированной выборки.

## Статус выполнения

- Код анализа и отрицательные unit/инфраструктурные тесты добавлены на **исследовательской ветке**. Чистая схема проверяется 4 тестами, включая отрицательную консервацию расхода и безлимитный урок; весь legacy audit из #67/#69 сохраняется.
- GitHub Actions на этой ветке настроены выполняться именно с `VITE_CONTENT8_PREVIEW=1`. Обычный workflow также проверяет C8-touch; JSON-артефакты первых двух частей хранятся с retention 7 дней.
- **Реальные численные распределения Q1b и новые глубокие выигрыши до успешного выполнения hosted CI: NOT EXECUTED / UNVERIFIED.** Предыдущие 505/325/263/203 — это подтверждённые цифры **Q1**, а не новый результат Q1b. Ни одна таблица затрат не заполняется предположительными числами.
