## Находка 1 — P1: сертификат альтернативных решений проверяет почти только пропуск карты из сброса

В tools/content/build-c8-wave.ts функция inspect собирает возможные альтернативы только на шагах transfer исходного выигрышного маршрута до 85% его длины. Если исходный ход переносит карту из waste, а можно нажать draw, вариант получает missedWaste=true. Затем auditChoices ставит **все missedWaste перед альтернативными transfer**, смотрит максимум 16 кандидатов и останавливается после двух отличающихся по длине выигрышных маршрутов. Выбор кандидата допускает уровень при наличии хотя бы одного такого маршрута; отдельное наличие другого осмысленного transfer не требуется.

**Независимый пересчёт опубликованных JSON для 65 уровней 16–80:**

| Подтверждённые факты | Количество |
| --- | ---: |
| Уровней и главных выигрышных маршрутов | 65 |
| Сохранённых альтернативных выигрышных маршрутов | **109** |
| Из них первое отличающееся действие — draw | **109 / 109** |
| Из них первое отличающееся действие — иной перенос карт | **0 / 109** |
| С меткой missedWaste=true | **109 / 109** |
| Более коротких, чем опубликованный witness | **43** |
| Более длинных | **66** |
| Испытано проб альтернатив по паспортам | **650** |
| Solver не разрешил исход этих проб в своём лимите | **105** |

**Интерпретация:** все эти альтернативы проходят под нашими Rules 3 и подтверждают, что можно тянуть из колоды вместо забора доступной карты сброса. Но они **не доказывают** существование интересного выбора между двумя разными переносами, карточными категориями и позициями. Также 43 более коротких альтернативы означают, что авторский witness не является доказательством оптимальности. Поле otherWins в коде обозначает совпадение длины или ранее отмеченного шага, а не универсальное число содержательных альтернатив. 105 unresolved — **ограничение поиска**, а не доказательство тупиковых ситуаций.

Это не доказательство отсутствия таких решений в игре и не причина автоматически переписывать 65 уровней. Это подтверждённый **пробел в метриках качества**, который не закрывает ни зелёный CI, ни существующие passports.

### Q1 — обязательное доисследование выбора

Не меняя опубликованные Deal ID:

1. В выбранных ранних/средних/поздних состояниях каждого witness перечислить разные легальные transfer: из tableau и waste, на foundation и tableau. Убрать дубликаты по итоговому состоянию доски.
2. Стратифицировать отдельно пропуск waste через draw/recycle, **другой перенос карты**, **другую цель переноса**, **другого лидера/категорию**. Не позволять большому числу draw вытеснять все transfer из лимита 16 проб.
3. Для реального альтернативного transfer записывать тип, источник, цель, ход, outcome FOUND/UNKNOWN/NO_WIN_PROVEN и независимый путь выигрыша либо честную неопределённость. Нельзя превратить timeout bounded solver в доказанное поражение.
4. Выпустить матрицу по уровням 1–80: количество доступных разных transfer, проверенных, выигрышных, UNKNOWN, draw-skip, recycle; отдельные предписания для первых обучающих уровней. Разрешимость и «несколько интересных ходов» — разные критерии.
5. Предлагать конкретные перевёрстки только если данные и человеческий плейтест показали недостаточную вариативность. Любое изменение принятой раскладки — новая immutable версия и тесты SaveStore/Undo/Hint.

## Находка 2 — P1: recycle почти не востребован опубликованными выигрышными маршрутами

Всего в **65** главных witness уровней 16–80 есть **ровно один** recycle (уровень **21**). Среди **49** witness уровней 32–80 recycle отсутствует полностью. Это **не значит**, что он не нужен другим стратегиям или что пользователи не нажимают recycle. Это значит, что наш авторинг почти не демонстрирует использование существенной механики колоды за пределами unit-тестов.

Q2 — построить выборочные маршруты, где recycle хотя бы стратегически полезен или нужен, отдельно доказать порядок повторной выдачи и бюджет, Hint/Undo и отсутствие тупика. Плейтест на Android: последний stock, завершение waste, recycle, следующий draw и проигрыш/продолжение. Если механика фактически не играет роли в дизайне кампании, решить с владельцем, где обучать/использовать её, **не исключая** из roadmap.

## Находка 3 — P1: Hard/Peak обозначены геометрией, а не измеренным опытом

В authoring коде tier=superhard при 5 столбцах, hard при 78+ картах, иначе normal. В 49 поздних уровнях используются четыре повторяющиеся структурные формы в адаптированном семишаговом ритме. Свободный запас ходов **в записанных победных witness**:

| Профиль 32–80 | Уровней | Остаток ходов в witness |
| --- | ---: | ---: |
| Rest (44 карты) | 7 | **7–12** |
| Standard (64 карты) | 21 | **11–16** |
| Hard (78 карт) | 14 | **23–26** |
| Peak (96 карт) | 7 | **28–33** |

Больше свободных ходов на Hard/Peak **не означает**, что там легче играть: больше карт могут требовать больше планирования. Установленное ограничение — формальные теги Hard/Peak **не являются проверенным рейтингом реальной сложности**. Ни длина witness, ни выигрыш модели не заменяет измерений действий и затруднений игрока.

Q3 — показать двум или более игрокам, включая неопытного, маршруты уровней 32/33/36/38 и 53–59; проверить контрпримеры 67 (малый slack), 78/80 (поздний Hard/Peak). Записывать время активного решения, первый неверный выбор, необходимость подсказки, неожиданный recycle, колебания >15 секунд, окончательный результат, понятность «Сложный» / «Очень сложный». Использовать настоящие касания на физическом Android 320×568 с нативным баннером. Вся UX/баланс-переоценка после наблюдений, не перед ними.

## Статус открытых веток и честность доказательств

Изученная цепочка CORE0 #48 → CORE1 #49 → CORE2 #51 → CORE3 #55/#57 → CORE4 #58/#60 → CORE5 #62/#63/#64 остаётся **серией вложенных открытых PR**, а не единым уже принятым релизом. Это не отменяет необходимость физического устройства и владельческой оценки.

Последняя CORE-5 ветка содержит **114 source IDs**, статусы 39 IMPLEMENTED_UNVERIFIED, 4 IN_PROGRESS, 48 ROADMAPPED, 13 EVIDENCE_GAP, 9 BLOCKED, 1 DEFERRED, **0 ACCEPTED**. Research source baseline active C8 обновился до kit PR #93 (то же число IDs, более точный AZUR preset), а CORE5 ещё на более раннем 114-ID снимке. При интеграции нужно синхронизировать **новые доказательства**, не возвращая старые документы и не затрагивая игровую работу.

**Все 114 систем остаются в общей программе**, включая рекламу, IAP, события, прогрессию и ассисты. Данный PR не удаляет и не объявляет ненужной ни одну из них; не меняет игру, арт, значения экономики, campaign ID или save schema.
