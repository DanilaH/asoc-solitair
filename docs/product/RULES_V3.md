# Правила 3: нижняя тема и совместимость

Уточнение владельца от 12.11.2026, реализовано в 0.10.0/code18. Этот контракт заменяет разрешение предмет → нижний лидер из прежнего §4.2. Остальные правила, лимиты ходов и числовая экономика сохраняются. Rules/content/balance: **3/5/3**.

| Источник → цель | Результат |
|---|---|
| Предметы → предметы своей категории внизу | Объединение целых доступных групп |
| Предметы → тема своей категории внизу | Отказ: «Сначала перенесите тему в верхний слот» |
| Предметы → группа с темой внизу | Тот же отказ, даже если у темы уже есть участники |
| Тема или группа с темой → предметы своей категории внизу | Разрешено; тема остаётся спереди. Это отдельное направление, его не запрещали |
| Доступная группа → пустой нижний столбец | Разрешено |
| Тема или группа с темой → пустой верхний слот | Запускает верхний сбор; полная категория завершается сразу |
| Предметы → запущенная категория наверху | Разрешено для своей категории; сохраняются ordered-префиксы |
| Предметы → пустой верхний слот | Отказ: сначала нужна тема |
| Карты другой категории → занятая цель | Отказ |
| Верхний слот → любое место | Перенос недоступен |
| Последняя карта сброса → цель | Те же ограничения; предыдущие карты веера недоступны |
| Пустая опора Joker → первая группа | Разрешено по прежнему правилу Joker. Закрытая им тема ниже границы не является целью |
| Занятая опора Joker → ещё одна группа | Прежний отказ: держит только одну группу |

Неверный drop не расходует ход, charge или Undo. Progress серии сбрасывается по прежнему контракту; cancel вне цели его сохраняет. Draw/recycle, очистка, открытие карт и ключей, порядок, победа последним ходом и награды не менялись. Drag, tap, подсветка цели, solver и Hint проверяют один переход движка.

## Старые попытки

`Save.rulesVersion=3` обозначает совместимую оболочку. `Board.rulesVersion` закрепляет правила конкретной попытки и её снимков Undo. Кампания и daily могут иметь разные версии одновременно.

- Правила старых v1/v2, content-v1–v5 сохранений переводятся в явный `board.rulesVersion=2`, с прежним полем, бюджетом, историей, attemptId и ресурсами.
- Обновление приложения, продолжение, смена режима и Undo не переключают правила начатой партии.
- Повтор, следующий уровень или новая daily создают поле по правилам 3. Подтверждение повтора старой партии объясняет смену правила.
- При v2 Hint использует исходный путь; при v3 — отдельно проверенный новый. Версия входит в ключ состояния и аналитическое событие.
- Legacy `intro-001`, не доступный как новая обычная кампания, сохраняется под правилами 2. Первые уровни обычной кампании используют правила 3.
- Шесть изолированных смысловых QA-прототипов остаются под правилами 2, чтобы не смешивать смену правил с незавершённым контентным экспериментом. Лаборатория не входит в обычный APK.

## Банк и история

ID, семантика, изображения, все исходные порядки, бюджеты, original winningPath и daily-v1 rotation сохранены. **73 альтернативных пути** находятся в `src/content/rules-v3-paths.json`; неизменённые пути переиспользуются. Отдельно исправлена девятикомандная демонстрация Joker, исходная сохранена как legacy. Все 80 кампаний и 28 daily проходят без помощников. Уровень 19 остаётся 45/45: раннее извлечение baking_2 освобождает верхний слот вовремя.

Undo хранит последние **300** полных транзакций. Все старые снимки сначала проверяются, затем удаляются только самые ранние сверх лимита. Это применяется к активной и припаркованной попыткам, без возврата charges/серии/монет. Неверные snapshots, даже за пределами сохраняемых 300, не скрываются обрезкой. Неизвестные правила, смешанные версии Undo, неверные верхние группы, частично collected и закрытые карты в открытых зонах отвергаются без перезаписи исходного файла.

Новая проверка банка: [rules-v3.json](../validation/rules-v3.json). Прежние per-deal записи остаются историческим подтверждением старых путей; полные новые записи создаются в `.validation/records/`. Независимый переходный прогон — `tools/verify-rules-v3.ts`.
