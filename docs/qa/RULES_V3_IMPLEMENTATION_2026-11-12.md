# Исправление правил и сохранений — 0.10.0/code18

Владелец разрешил реализацию после [независимого аудита](RULES_AUDIT_2026-11-12.md). [Точный контракт](../product/RULES_V3.md): в новой кампании/daily предметы не принимаются на нижнего лидера, включая уже собранную с ним группу. Верхний сбор работает по-прежнему. Обратное направление «лидер → предметы» остаётся допустимым; его не запрещали.

## Сделано

- Движок возвращает конкретный отказ без хода/charge/Undo; tap, drag, highlights, solver и Hint используют тот же переход.
- Каждая доска и Undo имеют свою версию правил. Старые активные/припаркованные попытки сохраняют v2. Новые и повторные обычные партии получают v3. Подтверждение повтора старой партии объясняет смену правила. Ключ состояния и аналитика различают версии.
- Исходные определения, порядок карт, бюджеты, ID, original witnesses и daily rotation не переписаны. 73 текущих пути накладываются поверх исходных; оставшиеся 35 переиспользуются. Старые пути доступны Hint для старой попытки. Отдельно обновлена демонстрация Joker, с сохранением исходной.
- Уровень 6 остаётся 23/32. Для уровня 19 вручную проверена перестановка: baking_2 забирается при первом открытии, выпечка закрывается раньше, освобождая верхний слот. Он остаётся 45/45. Ни один бюджет не увеличен.
- История ограничена 300 транзакциями при обычных действиях и размещении Joker. Загрузчик восстанавливает старые длинные активные/припаркованные попытки: проверяет все снимки и удаляет только самые ранние сверх лимита. Поле, attemptId, кошелёк, charges, серия и журналы сохраняются.
- Загрузчик отвергает смешанные/безлидерные верхние группы, частичный collected, закрытые карты в открытых зонах и неверную открытость столбца. Версии истории не могут отличаться от версии доски. Повреждённый исходник не перезаписывается.
- Legacy intro-001 и шесть изолированных прототипов остаются на v2; это не новые обычные партии. Прототипы сохраняют прежний эксперимент с контентом.

Графика, компактная компоновка, числовая экономика, SDK-настройки и kit SHA не менялись. Оболочка сохранения остаётся schema1, rules/content/balance — 3/5/3.

## Воспроизведение

`npm run check`, `npm run test:browser`, `npm run qa:layout`. Проверка обеих версий oracle: Vite SSR-сборка `tools/verify-rules-v3.ts`, затем запуск полученного JS. `tools/content/revalidate-rules-v3.ts` проверяет/ищет только пути, пишет кандидаты в `.recording/`, не меняет раскладки и бюджеты. `tests/browser/rules-v3.spec.ts` проверяет именно новое правило, legacy → restart и восстановление старой 301-командной попытки.

Исторические `tools/audit-rules*.ts` воспроизводят дефекты 0.9.4 и не являются проверками исправленной версии. Публикация в store, production SDK, живые объявления и физический Android этим пакетом не подтверждаются.
