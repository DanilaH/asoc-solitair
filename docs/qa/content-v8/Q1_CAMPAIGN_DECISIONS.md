# C8. Аудит выбора ходов на 80 уровнях

Срез C8 из 0.20.3, игровой commit `b15c075004081ab42828f22012920462f318c782`. Каталог загружается через `campaignDeals` с включённым C8. В основной таблице пять раздач с особыми правилами и три с доступными бонусными слотами. Архивные исходники замещённых уровней, варианты директора и стартовые состояния с открытыми слотами идут с отдельными итогами. [Игровая ветка PR #68](https://github.com/DanilaH/asoc-solitair/pull/68)

## Что проверено

На 80 основных уровнях просмотрели **800 позиций** и проверили **889 альтернатив**. В 528 пробах первым альтернативным действием был перенос. Из них **325** завершились победой, в том числе **263** без возврата к эквивалентной исходной позиции. На 79 уровнях такие маршруты нашлись сразу. В отдельной проверке 70-го уровня нашлись ещё три. На всех 80 есть подтверждённый пример продолжения после другого переноса без возврата.

Для 203 переносов исход остался неизвестным. Доказанных тупиков по лимиту среди 889 проб не найдено. В начале 70-го уровня две проверенные ветки с переносом из первого во второй столбец остались неизвестными и после более глубокого поиска.

На основных маршрутах повторный круг есть на уровнях 5 и 21. В проверенных отклонениях повторный круг позволил закончить раздачу на **47 уровнях**, на 13 из них найденный маршрут не возвращал доску к прежней позиции. В некоторых выигрышных ветках круг просто тратит запас ходов.

В проверке правил обе модели Rules 3 совпали по 1 021 340 переходам и отказам на 311 маршрутах, в том числе на старых версиях правил. Реестр переноса покрывает 114 механизмов.

Из семи переносов пять завершаются победой, три обходятся без возврата к исходной доске. SHA-256 `876fee1bf7d6d11202ae6381e78a46ab3442bcb4229801919499232ce349a349`.

Результаты дают конкретные позиции для плейтеста. Изменение раскладок требует наблюдений за выбором людей в этих позициях.

## Как проверяли

- Победный маршрут и сохранённые авторские альтернативы воспроизводились в Rules 3 и независимой модели. Проверяли до десяти равномерно распределённых позиций на основном маршруте, от начала до последнего хода. В этих позициях сравнивали полный список разрешённых действий и получившиеся доски. Перестановки равнозначных слотов считались одним результатом. Позиция закрытого столбца сохраняла значение.
- В каждой трети маршрута проверяли первый доступный пример каждого класса альтернатив. Если среди выбранных позиций не было альтернативного повторного круга, брали ближайшую к концу колоды позицию, добирали остаток и проверяли круг с фактическим расходом ходов. Число перед альтернативным действием в отчёте — номер хода в исходном маршруте. Для повторного круга `prefix` содержит дополнительные доборы.
- `WIN` содержит полный маршрут, проверенный обеими реализациями с остатком исходного лимита. Маршруты с возвратом к эквивалентной доске до выбора отмечены `loopsBack`. `NO_WIN` означает, что обе реализации исчерпали поиск в пределах оставшихся ходов для этой ветки без помощников. `UNKNOWN` означает, что лимита поиска в 320 позиций на модель не хватило для вывода. В обычных раздачах дополнительный поиск до 100 позиций используется для нахождения побед, а доказательство отсутствия победы требует исчерпания обеих моделей.
- Это проверка правил поля. В первых уроках игра может требовать конкретный жест, применение подсказки, отмены или Джокера. Нельзя переносить числа по этим уровням на первую сессию. Открытые бонусные слоты моделировались с начала партии, после открытия обычными правилами. Субъективная сложность, понятность уроков и выбор людей остались для плейтеста.

Команда `npm run qa:campaign-decisions` пишет `.authoring/content8/campaign-decisions.json`. В файле есть исходное действие, альтернатива, карты, решение и остаток ходов. Нумерация столбцов и слотов в JSON начинается с нуля. `t` — нижний столбец, `f` — верхний слот, `w` — сброс, `d` — добор, `r` — повторный круг.
