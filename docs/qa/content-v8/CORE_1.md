# Content 8 CORE-1

База — [CORE-0 #48](https://github.com/DanilaH/asoc-solitair/pull/48). Пакет добавляет воспроизводимый офлайн-авторинг и паспорт кандидата.

| Доказанный участок | Реализация и проверка |
| --- | --- |
| `hitapps-stock-dealer` | Используется существующий Packed/EmbeddedRandom и опубликованные хеши EN2/EN7. Все 15 сохранённых раздач C8 воспроизводят точный stock и каждый столбец по записанному seed. |
| `hitapps-negative-seed-request-path` | Отрицательный запрос выбирает seed в диапазоне `[0, INT32_MAX)` из отдельного источника. Паспорт сохраняет запрошенный и применённый seed. Энтропия для будущих наших запросов поступает из `node:crypto`. |
| `hitapps-candidate-priority` | Ограничение 100 применений, первая лучшая раздача при равенстве, ранний выход по явному допуску. При достижении лимита восстанавливается выбранный seed и повторяется Shuffle. Если нет выигранного кандидата, авторинг возвращает `NO_WIN`. |
| `hitapps-initial-shuffle-final-pipeline` | Свежее приготовление проходит Initial → Shuffle → Final. Кандидаты проходят Shuffle перед симуляцией, выбранная раздача проходит Final один раз. Известный порядок аплаеров закреплён тестом. Отдельные баллы применения и сбоя не подменяют результат симуляции. |

Паспорт новых результатов содержит хеш конфигурации, число проверенных кандидатов, причину выбора, хеши поля после Shuffle и Final, флаги эффектов, базовый и фактический бюджет и хеш маршрута, переигранного независимой моделью. Наши условия отбора и Rules 3 обозначены как адаптация. Механики EasyDeals, Priority/Equality для игрока и одноразовый reseed относятся к следующим пакетам. Авторинг пишет результат вне каталога опубликованного контента. Подстановка в приложение происходит отдельным изменением банка с новым ID при смене версии.

[Исходный отчёт Kit](https://github.com/DanilaH/mini-games-kit/blob/57bffb395e06200dc9f147c6f52f0128b4a4d370/research/games/association-solitaire/2026-11-18-hitapps-plain-replay/README.md) содержит агрегат 752 снимков Python/C++. Для независимого прогона TypeScript по всем 752 нужен числовой экспорт исходных 188 геометрий. [Проверка агрегата](../../../tools/qa/verify-hitapps-plain-prefix.ts) принимает формат `{sourceXapk,rows:[{locale,position,stockSize,columnSizes}]}` и пробует семена 0, 1, 42 и 43. Хеши четырёх опубликованных векторов проверяются в CI. Живые исходные доски, фактический выбор алгоритма и параметры активации остаются открыты.

Сигнатуры опубликованных раздач, сохранений и Undo продолжают использовать существующий runtime. Отдельные настраиваемые аплаеры нужны для CORE-2/4. Для AZUR нативные тела GenerateCards/DealCards остаются предметом исследования.

## AZUR 1.3.3.8

По [новому нативному исследованию](https://github.com/DanilaH/mini-games-kit/pull/80) подготовка вызывает GenerateCards, затем DealCards. [Модель AZUR](../../../tools/content/azur-dealer.ts) отдельно воспроизводит один проход Fisher–Yates, передаёт диапазон `[0, remaining)` вызывающему RNG, раскладывает столбцы по `FirstColumnCards + columnIndex` и открывает только их верхние карты. Остаток хранится в порядке входа `Deck.Initialize`. Тесты проверяют 0/1/2/100 карт, длины столбцов, выход за диапазон и нехватку карт. Текущий Content 8 сохраняет ранее выбранную выдачу Hitapps. Исходный Unity RNG, точный путь пресетов и живые снимки остаются открыты.
