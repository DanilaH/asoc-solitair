## 3. Обязательная единица сравнения (не статичный скрин)

Для каждой из выбранных сцен с одним и тем же `dealId`, точной исходной `Save.attempt` и размером viewport зафиксировать:

`до ввода → pointer down / tap → lift & target preview → release → model accepted/rejected → контакт с destination → settled category/flip/reflow → следующее разрешённое действие`.

Сохранить для каждого эпизода **OBSERVED / INFERRED / UNKNOWN**, источник и timecode, а у нашего запуска — exact SHA, rules/content/balance и `attemptId`. На всём цикле отдельно отмечать момент, когда логический ход уже принят, момент начала cue, момент визуального контакта, активную область pointer, геометрию цели и возможность сделать следующий ход.

Не утверждать точную синхронизацию звука/вибрации, если нет аппаратной записи/слушания; браузерный WebAudio mux не заменяет физический динамик. Если исходное видео показывает только 2D картинку, не приписывать «тактильную приятность конкурента» как измеренный факт.

## 4. Пакеты работы (не более трёх подтверждённых правок за итерацию)

### F0 — Базовая диагностика и gap matrix. ОБЯЗАТЕЛЬНО, без переделки игры

1. Повторить 8 сцен на настоящих C7 раскладках: **1/2 (первый запуск), 4 (буфер/отмена), 8 (Joker), 30 (ordered), 49 (ключи), 71/76 (плотная доска), 80 (финал), daily (режим)**. Для компактного и длинного C7 выбрать точные состояния из реально принятого банка, не собирать произвольные картинки.
2. Скринкаст на `360×780` и `320×568`; чувствительность `320×480` и `393×851`, четыре положения колоды, stock/recycle, short tap/drag/long press, попадание картой/пальцем, escape/cancel, Undo/reload, reduced motion. Сначала внутренние тапы без тестового auto-scroll.
3. Для двух подряд действий и их визуальных хвостов сопоставить реальные `Save/Board` до/после с pure model: карта не исчезает раньше контакта, название/превью верхней категории не мигает, результат/кошелёк не меняются от повторного рендера, а следующий жест не блокируется ненужным wait.
4. Сделать **gap matrix**: `reference scene/timecode → our build/state/input → actual difference → severity → smallest fix → test → status MATCH / GAP_CONFIRMED / INTENTIONAL_DIFFERENCE / NOT_INSPECTED`. Если главного gap нет — **закончить аудит честно**; не искать work ради работы.

### F1 — Плотность действия и причинный отклик. P0 ТОЛЬКО ПРИ GAP_CONFIRMED

Обязательные свойства (уже реализованы — проверять, не переписывать):
- поднятая карта/пакет сохраняют видимую «бумагу» исходной позиции и правильный счетчик количества, идут непосредственно за пальцем; никакого laggy следования из-за анимации выбранной карты;
- до release цель понятна, неверный drop возвращается локально, off-target cancel не имитирует «неправильную ассоциацию», ошибка не тратит ход; не принимать двусмысленные геометрические near-miss вместо человека;
- после принятого движения визуальная посадка не уступает новому состоянию foundation раньше контакта; двухфазное раскрытие, появление следующей карты и боковой reflow образуют одну причинную цепочку; Undo прерывает декоративный хвост, не откатывает полученные ранее ресурсы;
- при `4/4` или `3/3` на короткое время читается **полная** категория до compact clear; пакет большой группы имеет более выразительный **локальный** акцент, чем одиночный перенос, **без нового full-screen торжества и без обязательной паузы**;
- новая команда, быстрый перенос/Undo и фон отменяют устаревшие tween/callback по **generation/owner**, а не создают вторую игровую модель.

Если на эталонном уровне крупный пакет выглядит так же как одиночная карта, допускается **один локальный вариант** feedback с ограничением интенсивности по размеру пакета (например, чуть сильнее settle/микроакцент целой темы), но не новая система частиц и не изменение правил.

**Порог готовности:** ноль карт-призраков, перепрыгиваний под пальцем, пустой foundation между контактом и результатом; один model-command, один списанный ход, один реальный reward credit. На тестовой паре короткой/длинной стопки **до/после** визуально считывается физический контраст; если он не улучшает восприятие — оставить baseline.

### F2 — Звук, haptics, кнопки. P0 ПРИ ПОДТВЕРЖДЁННОЙ ПРОБЛЕМЕ

1. **Прослушать** в 1× нормальной скорости звуки AZUR S2 и нашего финального native APK на соответствующих событиях, **раздельно**: lift, gather, ordinary place, draw/recycle, invalid, Undo, complete category, coin arrival, win. Записать, где звук реально несоразмерно громкий/резкий/дублируется/запаздывает. Нельзя копировать чужие звуковые файлы.
2. Проверить существующие **15 оригинально лицензированных CC0 PCM** и ограничение **четырёх голосов**; пропущенный звук не должен звучать с задержкой после следующего действия. Защита от дублирования и `audio focus` после fullscreen ad обязательны.
3. Звук принятого переноса и лёгкая вибрация принадлежат **реальному контакту**. Отказ — короткий и мягкий; gather всей группы не разложен на 7 ударов; категория/финал отличаются по интенсивности, но обычные действия не перегружены громкими фанфарами. При mute/haptics-off — полная тишина/отсутствие вибрации для соответствующего канала.
4. Проверить состояния UI-кнопок: `pressed → released`, `pointer exit/cancel`, `disabled`, `pending` для Hint, Undo, Play/Next, close, continue; хитбокс минимум удобен и не пересекает системные inset. Не создавать ещё один общий ButtonTween wrapper при существующих CSS/native средствах.
5. **Reduced motion:** мгновенно читаемые статические состояния, сохранены все доступные действия/подсказки/награды, не прерывается звук/вибрация «из прошлого» после смены режима.

Не заменять все звуки ради «похожести на Unity». Исправлять лишь зафиксированные конкретные чрезмерные/слабые cues либо timing; provenance новых исходников/лицензий обязателен.

**Приёмка F2:** небольшое видео с аудио/скринкастом на исходной 1× скорости, реальный телефонный чек-лист по 9 типам событий, до/после в одном и том же упражнении. Если у агента нет телефона, он делает только код/браузер/пакет измерений и ставит **PHONE UNKNOWN**.

### F3 — Переходы, награды, безопасный UX. P1 ТОЛЬКО С КОНКРЕТНЫМ ДЕФЕКТОМ

- `win → complete reward → shown wallet → Next`: результат короче обычной партии; пользователь знает, какие монеты/Hint получил, путь монет защищает title/amount/CTA. Ранний `Next`/close/reload не теряет durable reward и не выдаёт её повторно. Кнопка следующего уровня доступна без обязательного просмотра всех частиц.
- `exhausted → Undo / optional earned continuation / Replay / back`: все доступные **реальные** действия помещаются на портрете, непоказавшаяся реклама не стирает board, отказ/reward callback не имитируют success. Не скрывать и не задерживать кнопку Restart по образцу AZUR. Не вводить coin-priced +moves в feel-пакет.
- `pause / home / daily / resize / Android background / ad return`: нет «повторной раздачи» сохранённой попытки, нет висячей ghost Hint, не остаются старые звуки и touch capture, wallet и открытые/припаркованные попытки неизменны.
- Новые C7 туториалы ordered/keys не запирают первый ход; показ первой встречи соответствует [C7 doc](../content/CONTENT_V7_IMPLEMENTATION_SPEC_2026-11-18.md) **после слияния** и не играет часть уровня за человека.
- Сравнивать с AZUR как с приёмом последовательности, **не импортировать rewarded x3/x5, таймер рестарта, Play Pass, новые модалки и рекламные размещения**.
