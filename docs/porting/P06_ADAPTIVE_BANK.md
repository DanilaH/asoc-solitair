# P06 · Офлайн-банк для уровней 16–80

`npm run qa:adaptive-bank` строит 130 неизменяемых кандидатов `*-tight-r2` и `*-relief-r2` для 65 уровней. Normal остаётся исходной раздачей. Tight −5%, relief +10% повторяют существующую формулу R1. В этих вариантах различается бюджет, а порядок карт и правила исходного уровня сохраняются. Для новой раскладки с изменённым порядком карт потребуется отдельный паспорт и доказанный маршрут.

- Движок и oracle воспроизвели каждый шаг выигрышного маршрута у 130 кандидатов. Минимальный запас — 2 хода. Для каждого проверены сохранение хода, переключение на ежедневное задание, декодирование припаркованной партии, возврат и Undo. Отдельный контроль проверяет, что штатная выдача всех 65 уровней оставляет исходный Deal ID при обеих величинах штрафа и трёх поражениях.
- В `.authoring/c8-adaptive-bank/` пишутся `manifest.json` и `deals.json`; CI прикладывает их к PR. SHA-256 базы `a58b067ca9899fa6873f83a09c6ffeb60b0750a9be779e32879cb34839a466aa`, SHA-256 строк манифеста `0eff4b7ec2ac7ebdbcbae6024c80823187d8e2106f75910effbc9f694c1ae5a9`.
- Модель родного слота отдельно проверяет ContinueRequested → ExtraSteps, повторный RestartedLevelBegin → Restart с увеличением счётчика, и LevelWon → продвижение. Прежний продукт отдельно сохраняет одну запись после первой победы. Тесты текущей формулы проверяют границы 70/90, противоположный штраф, историю из десяти и отличие clean от adjusted. [Сверка с оригинальными точками входа](../qa/content-v8/Q2_DIRECTOR_SOURCE_DELTA_2026-11-21.md).

**NEEDS_OWNER для включения.** В активной кампании продолжают выдаваться варианты R1 на уровнях 11–15. Для 16–80 требуется отдельное решение по применению порогов 70/90, бюджету −5/+10 и облегчению после трёх проигрышей, в том числе если все десять результатов завершены с дополнительными ходами. P02 проверяет восприятие сложности. Оригинальные live-параметры, точное округление и восстановление исходной последовательности EasyDeals остаются P36. Три назначенных ID остаются в реестре с прежними уровнями приёмки.

## Игровая интеграция · 22.11.2026

Отдельная сборка `VITE_C8_OWNER_PREVIEW=director` подключает оба направления к выпуску новой попытки. Архив R2 включает основную кампанию 16–80, главу 81–87, английский вариант 81 и специальные поля, если их заданный маршрут укладывается в уменьшенный бюджет. Сертификация сравнивает каждый шаг игрового движка с независимым оракулом. Старые банк R1 и активные/припаркованные попытки продолжают разрешаться по своим ID. R2 меняет бюджет на той же раскладке. Альтернативный исходный seed и действующий remote config остаются неизвестны.

Запрос продолжения, включая no-fill, пишется в отдельный исходный слот и не выдаёт ходов. Продуктовая история успешного использования помощи остаётся отдельной от записи запроса. Нужны физическое Android, человеческий плейтест баланса и источник реальных параметров EasyDeals. KIT IMPACT: REUSE.
